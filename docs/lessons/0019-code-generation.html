Étape 7 en code : soixante lignes d'appel LLM, et trois garde-fous

À la fin de cette fiche, vous pouvez réécrire vous-même atelier/generation.py : le prompt qui interdit d'inventer, l'appel à l'API compatible OpenAI d'Ollama avec la bibliothèque standard seule, et les trois garde-fous CPU sans lesquels la commande semble gelée.

Le principe de l'étape. Conformément à la leçon 0006, la génération est un bonus : elle décore un retrieval qui tient déjà seul. Le module est minuscule parce que toute l'intelligence est ailleurs : il assemble un prompt qui impose la citation des extraits, poste une requête JSON à une API compatible OpenAI (le dénominateur commun de l'écosystème, qui rend Ollama et vLLM interchangeables), et borne la réponse. Le code n'utilise aucune dépendance : json et urllib.request suffisent pour un appel HTTP.

Le prompt système : trois interdits, un mot de sortie

SYSTEME = (
    "Tu réponds exclusivement à partir des extraits fournis. Tu cites chaque "
    "information entre crochets avec l'identifiant d'intervention et la page du "
    "Journal officiel. Si les extraits ne permettent pas de répondre, tu réponds "
    "exactement : INSUFFISANT. N'invente jamais de date, de nom ou de page."
)

def construire_prompt(question: str, resultats: list[dict]) -> list[dict]:
    extraits = []
    for rang, r in enumerate(resultats, start=1):
        entete = (
            f"[{rang}] intervention {r['intervention_id']}, {r['orateur']}, "
            f"{r['chambre']}, {r['date']}, page JO {r['page_jo']}"
        )
        extraits.append(entete + "\n" + r["texte"])
    contenu = (
        "Extraits :\n\n" + "\n\n".join(extraits)
        + "\n\nQuestion : " + question
    )
    return [
        {"role": "system", "content": SYSTEME},
        {"role": "user", "content": contenu},
    ]

Le message système est le règlement du système : il fixe le contrat avant la conversation. Trois clauses comptent. Exclusivement à partir des extraits interdit la culture générale du modèle — sur un corpus OCR du XIXᵉ siècle, ce que le modèle « sait » de la IIIᵉ République vient de manuels, pas de vos pages. Citer entre crochets identifiant et page rend chaque affirmation de la réponse auditable d'un coup d'œil — c'est la provenance de la leçon 0008, jusque dans la syntaxe d'une phrase. Répondre exactement INSUFFISANT donne au refus une forme reconnaissable par un programme : une interface peut tester la chaîne exacte et proposer alors les extraits eux-mêmes, plutôt que de laisser le modèle combler le vide par de la vraisemblance. L'en-tête de chaque extrait (intervention, orateur, chambre, date, page) est là pour que la citation exigée soit matériellement disponible sous les yeux du modèle : un prompt ne peut pas faire citer ce qu'il ne donne pas.

L'appel : du JSON sur HTTP, avec la bibliothèque standard

def generer(question, resultats, config, timeout: int = 300) -> str:
    corps = json.dumps({
        "model": config.ollama_model,
        "messages": construire_prompt(question, resultats),
        "temperature": 0.2,
        "stream": False,
        "think": False,
        "max_tokens": config.ollama_max_tokens,
        "options": {"num_ctx": config.ollama_num_ctx},
    }).encode("utf-8")
    requete = urllib.request.Request(
        config.ollama_url.rstrip("/") + "/v1/chat/completions",
        data=corps,
        headers={"Content-Type": "application/json"},
        method="POST",
    )
    with urllib.request.urlopen(requete, timeout=timeout) as reponse:
        donnees = json.loads(reponse.read().decode("utf-8"))
    return donnees["choices"][0]["message"]["content"].strip()

L'URL n'est pas l'API native d'Ollama (/api/chat) mais sa face compatible OpenAI (/v1/chat/completions) : le corps de la requête et la structure de la réponse sont alors ceux du protocole OpenAI, et la seule ligne à changer pour passer d'Ollama (développement CPU) à vLLM (production GPU) est l'URL de base. La temperature de 0,2 écrase l'aléa : une synthèse documentaire doit être reproductible, pas inventivée. stream: False attend la réponse entière : l'atelier imprime un bloc, une interface web streamerait les tokens, mais le garde-fou du paragraphe suivant en dépend — sans flux, le client ne voit rien pendant toute la génération.

Les trois garde-fous CPU, gagnés à la suite d'un échec

Piège vérifié sur le terrain (leçon 0006, « le piège du tag »). La première version de cette étape restait muette puis expirait. Cause mesurée : le tag Ollama qwen3:4b sert aujourd'hui Qwen3-4B-Thinking-2507 (digest 359d7dd…, identique à qwen3:4b-thinking), une variante dont le raisonnement est inarrêtable — /api/show déclare thinking: values [true], default true — et dont le champ think: false est ignoré. En stream: False sur CPU (~7 tokens/s), la commande émettait silencieusement des milliers de tokens de raisonnement invisible : 2 391 tokens en 3 minutes 10. Le kit utilise donc qwen3:4b-instruct (variante hybride, qui honore think: false) et trois champs de la requête portent la leçon.
  • "think": False — désactive le raisonnement interne (les tokens de chaîne de pensée que le modèle s'écrit à lui-même avant de répondre) sur les variantes hybrides. Sans ce drapeau, ces tokens invisibles consomment la fenêtre et le temps.
  • "max_tokens": 500 (constante ollama_max_tokens de la configuration) — borne la réponse, et borne surtout le raisonnement résiduel si le modèle ignorait le drapeau : la boucle ne peut plus diverger sans limite.
  • "options": {"num_ctx": 8192} — agrandit la fenêtre de contexte : trois enfants de ~1 200 tokens plus le prompt atteignent la fenêtre serveur par défaut (4 096 tokens), et une requête trop longue pour le contexte est tronquée côté serveur, sans erreur pour le client — le genre de dégradation silencieuse qu'on préfère explicite.

Avec ces trois réglages et le bon tag, la chaîne complète a été vérifiée de bout en bout : 1 min 43 à froid sur CPU pour la question de l'exemple (mesure Ollama 0.40.12), à comparer des dizaines de millisecondes de la recherche seule — la génération reste l'étage lent, et c'est pourquoi elle est bonus.

Le branchement : rerank d'abord, génération ensuite

candidats = recherche.recherche_hybride(args.question, encodeur, config, client)
resultats = recherche.reranker(args.question, candidats, config, top_k=args.k)
reponse = generation.generer(args.question, resultats, config)
print(reponse)
print("\n— sources —")
for r in resultats:
    print(f"  [{r['intervention_id']}] {r['orateur']}, page JO {r['page_jo']}")

La commande generer réutilise l'entonnoir de l'étape 5 sans y toucher : le LLM reçoit le top-3 reranké, jamais davantage, et la liste des sources est imprimée depuis les payloads, pas depuis le texte du modèle — la trace de provenance ne dépend pas de la bonne volonté de la génération.

Comment le module est testé

  • test_prompt_impose_citations_et_refus (unitaire, hors-ligne) : le message système contient l'interdit hors extraits, l'exigence de citation et le mot INSUFFISANT ; le message utilisateur contient l'identifiant, la page et le texte de chaque extrait.
  • test_generation_reelle, marqué -m reseau : saute tant qu'Ollama n'est pas joignable, joue le vrai appel (question, trois extraits, réponse non vide) dès qu'il l'est — uv run -m pytest -m reseau.

À vérifier de votre côté : après ollama pull qwen3:4b-instruct, la commande uv run python -m atelier generer "que dit montjou de l'infrastructure aeronautique a laval ?" rend une synthèse dont chaque information porte un crochet de citation, suivie de la liste des sources avec leurs pages du Journal officiel.

Vérifiez que c'est acquis

1. Pourquoi taper sur /v1/chat/completions plutôt que sur l'API native d'Ollama ?

/v1/chat/completions est le protocole rendu public par OpenAI, devenu le dénominateur commun de l'écosystème : Ollama l'expose, vLLM l'expose, et passer du développement CPU à la production GPU ne coûte plus qu'un changement d'URL (leçon 0006). Les deux autres affirmations sont fausses : l'API native connaît la temperature, et think est un champ additionnel qu'Ollama accepte sur les deux faces.

2. Le mot INSUFFISANT impose au modèle une réponse exacte. Pour qui est écrite cette contrainte ?

Le lecteur profite du refus (une absence de réponse vaut mieux qu'une réponse fausse), mais la forme exacte sert d'abord la machine : testable par ==, elle permet à l'interface d'afficher alors les extraits en mode retrieval-first au lieu d'un texte. Une consigne du genre « dis poliment que tu ne sais pas » serait invisible pour un programme.

3. Le test -m reseau saute quand Ollama est absent, au lieu d'échouer. Pourquoi ce choix ?

La pyramide de tests de l'atelier distingue les marques : l'unitaire doit tourner partout (make test), l'intégration demande Qdrant, le test réseau demande Ollama vivant. Une dépendance externe absente n'est pas une régression du code : sauter avec un motif explicite garde la suite utile sur toutes les machines, et make test-complet exclut ces marques par nom.
