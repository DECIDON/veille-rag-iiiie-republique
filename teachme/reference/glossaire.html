Glossaire du cours

La référence à rouvrir : chaque terme du cours, en une ligne, avec sa leçon. Définitions alignées sur la veille (21/10/2026).

Axe 1 — Les données

Post-OCR / normalisation (0001)
Nettoyage du texte OCR (Unicode NFKD, apostrophes, artefacts) par règles et dictionnaires d'alias — jamais par écrasement de l'original.
JSON canonique par intervention (0001)
Format intermédiaire unique du corpus : une entrée = une intervention, avec date, chambre, orateur, page_jo, arK, text_brut + text_normalise.
Chunk / chunking (0002)
Granulat indexé / acte de découpage. Ici : par intervention (frontières documentairement vraies), ~500–2 000 tokens.
Parent-document (0002)
Pattern « indexer fin, restituer large » : chunk-enfant cherché, séance-parent rendue. ParentDocumentRetriever / AutoMergingRetriever.
Late chunking (0002)
Encoder le document entier (modèle 32 k) puis découper les embeddings — chaque chunk porte le contexte global (arXiv 2409.04701). Option GPU uniquement.
RAPTOR (0002)
Arbre récursif de résumés par LLM pour questions panoramiques ; coût = tout le corpus résumé ; résumés non citables.
Embedding dense (0003)
Vecteur de sens (ex. 1 024 float32) ; similarité cosinus ; capture la paraphrase.
Embedding sparse (0003)
Poids appris par terme dans un vocabulaire géant — un BM25 neuronal ; fidèle au terme exact (noms propres, OCR).
bge-m3 (0003)
Modèle MIT 568 M fournissant dense + sparse + ColBERT ensemble ; ~1–3 Go RAM, faisable CPU ; la clé de l'hybride sans moteur séparé.
MTEB / MMTEB / MTEB-French (0003)
Bancs d'essai d'embeddings ; présélection uniquement — notre corpus XIXᵉ est hors distribution.
ANN / HNSW (0004)
Recherche du plus proche voisin approchée (graphe HNSW chez Qdrant) : millisecondes contre quelques voisins ratés — à évaluer, pas à supposer.
Payload (0004)
Métadonnées JSON indexées d'un point Qdrant ; support des filtres « chambre / date / orateur » avant ou après l'ANN.
Quantification (0004)
Compression des vecteurs : int8 ×4 (perte minime), binaire ×32 (+ rescore exact). Transforme 60 Go en ~15 Go.
Enrichissement / métadonnée dérivée (0001–0002, 0011)
Thème ou phrase-résumé généré pour une intervention : champ indexé du record (jamais doc séparé, jamais texte cité), produit par un étage dédié versionné entre normalisation et embedding ; filtrable seulement si vocabulaire contrôlé ; affiché comme enrichissement machine, jamais en remplacement du verbatim.
Vocabulaire contrôlé (0009, enrichissement)
Liste fermée de valeurs de thème : sans elle, pas d'agrégation facettable possible sur un champ dérivé.
BM25 (0003, 0005)
Fonction de score lexicale de Lucène : fréquence du terme avec saturation, rareté (idf), normalisation par la longueur. Pas un modèle, pas de poids appris — indispensable sur corpus OCR bruité.
Recherche hybride (0005)
BM25/lexical + vectoriel en parallèle, puis fusion. Le « socle recommandé » de la veille.
RRF (0005)
Reciprocal rank fusion : fusion par rang (pas par score), robuste car les échelles des moteurs sont incomparables.
Reranker / cross-encoder (0005)
Relit requête + chunk ensemble pour re-scoring très précis, sur top-k uniquement (ex. bge-reranker-v2-m3, Apache-2.0).
recall@k / nDCG (0005)
Métriques d'évaluation : présence des bonnes sources dans le top-k ; ordre en plus. Jouées sur ~200 Q&R annotées en interne.
Serving / API OpenAI-compatible (0006)
Serveur de LLM derrière un dialecte unique : Ollama (MIT, dev/CPU) → vLLM (Apache-2.0, prod GPU).
GGUF / Q4 (0006)
Format de poids quantifiés de llama.cpp ; Q4_K_M ≈ 0,5–0,6 octet/paramètre → un 8B ≈ 5 Go.
MoE (A3B) (0006)
Mixture-of-Experts : Qwen3-30B-A3B, 30 B paramètres dont ~3 B actifs par token — meilleur compromis CPU.
Retrieval-first (mode sans LLM) (0006)
UX CPU par défaut : recherche hybride + facettes + extraits surlignés ; la synthèse LLM n'est qu'une option.

Axe 2 — L'interface web

Turnkey (0007)
Plateforme RAG complète auto-hébergée (RAGFlow, Kotaemon, Onyx…). Défaut structurel : elle recopie le corpus dans son index.
Stack composée (0007)
Assemblage de briques permissives autour d'un index externe en lecture seule — la voie retenue.
Open-core (0007, 0010)
Noyau open source + fonctionnalités sous ee//enterprise/ (Onyx, LiteLLM).
Chat-with-citations (0008)
Pattern UI : marqueurs [^n] cliquables + panneau de sources + lien vers vue stable de la page.
arK (0008)
Identifiant pérenne de la BnF ; dérivé par page, il permet les liens profonds Gallica qui authentifient une citation.
IIIF / manifeste (0008)
Standard d'exposition d'images de pages ; API IIIF BnF + visualiseur libre (Mirador, Universal Viewer).
Facette (0009)
Compteur par valeur de métadonnée (date, chambre, orateur) = agrégation déterministe de l'index — jamais un LLM.
Text-to-SQL (0009)
NL→SQL (Vanna MIT, WrenAI Apache-2.0) ; ≤ 37 % de réussite selon les benchmarks → complément seulement, SQL affiché.
Permissive / copyleft / AGPL (0010)
MIT-Apache-BSD (libre sans contrepartie) ; GPL (obligations à la redistribution) ; AGPL (+ section 13 : usage réseau = distribution).
Source-available (0010)
SSPL / Elastic-2.0 : code consultable, pas open source OSI → Elasticsearch écarté au profit d'OpenSearch.
Clause de marque (0010)
Interdiction Open WebUI de masquer le branding au-delà de 50 utilisateurs / 30 jours — seuil quasi sûr pour un service public.
OIDC / RBAC (0007)
Authentification déléguée (SSO) et rôles ; dans le noyau Chainlit/Open WebUI, hors CE chez Onyx.

Termes écartés par la veille mais cités pour mémoire : SPLADE (sparse neuronal FR, Apache-2.0), ColBERT (3ᵉ mode de bge-m3), MRL (dimensions tronquables de Qwen3-Embedding), RRF/DBSF (deux fusions Qdrant).

Un terme absent ou mal défini ? Dites-le à l'agent dans OpenCode : le glossaire est vivant.
